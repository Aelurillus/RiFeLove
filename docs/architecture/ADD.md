# Architecture design document

Version 0.1. This document records implemented boundaries and the remaining architecture required by the complete Master Plan.

## Layering

Desktop and CLI adapters submit application-service operations. Task, model, device and progress services own user-facing state and orchestration. Named local settings profiles are stored by the desktop configuration store and can be transferred as one versioned JSON profile at a time; import validates the schema, values and local-only file URLs before persistence. The full reusable ProfileService remains planned. The core pipeline schedules rational presentation times and coordinates media, quality, interpolation and GPU resources. Backend implementations own FFmpeg/CUDA/ONNX/TensorRT contexts. UI code must not own those contexts.

The CLI adapter calls media and native video pipeline public C++ APIs. The desktop's `StudioController` marshals owned values between QML and the standard-C++ `application::ProcessingService`. `QueueController` and its Qt worker wrap `application::TaskQueue` and the shared `ImportService`; the UI gets a `QAbstractListModel` projection and never calls media/GPU code. The queue worker owns database access and job execution off the GUI thread, while callbacks return immutable values to the controller thread. No vendor context is owned by QML or either controller. The offline Model Center uses the same worker boundary to verify local packs and persist the catalog/default selection. RIFE pack schema v2 verifies model, license, source-manifest and validation-report hashes and exposes the declared license, upstream commit, numerical profile, input profiles and validated backends. Legacy v1 packs remain readable and are visibly identified as lacking sidecar hash binding. The hashes provide local consistency checks, not source authentication; downloads, a trusted provenance registry, multiple qualified profiles, advanced preferences and complete task-history management remain required.

`application::TaskQueue` owns configured-task execution and live database ownership. The common executor admits one job at a time per process and protects source bytes with a native read lease. `task_details` stores versioned configuration/identity/progress/result payloads beside the existing task state machine. Batch insertion and state/result publication are transactional; progress is throttled. Jobs pin model descriptors when queued and retain checked source/model identity after preparation. `ImportService` performs bounded local file/folder discovery, stable path deduplication, output allocation, probe/color eligibility checks and stop-aware atomic enqueue. Recovery requires the OS ownership lock, marks active configured work interrupted, and preserves history. Configured video jobs now write validated, hashed, video-only checkpoints and expose explicit resume after interruption; the pipeline decodes from the source beginning and skips the committed output prefix before final assembly. See [queue contracts](../development/QUEUE.md) for the exact resume and restart semantics. Studio and Queue share a local named settings-profile store with schema-checked single-profile JSON import/export; CLI profile management, qualified quality presets, broader model lifecycle work and full audit/history pagination remain incomplete.

## Implemented media contract

`MediaEngine::probe` returns stream/container/chapter metadata in standard C++ values. `decodeVideo` yields `DecodedFrame` objects with rational PTS, optional duration, native pixel planes, color and reference-counted ownership. Retained frames remain valid after decoder closure. The interface does not require callers to include FFmpeg headers. Missing timestamps are explicit, and observed cadence accounts for input-time-base quantization.

The comparison viewer uses `MediaEngine::decodeFrameNearTime` for paused frame inspection. It seeks to a preceding key frame, decodes in presentation order, chooses the nearest timestamped frame and returns the adjacent PTS values with a bounded RGBA image. The conversion is limited to the existing tagged SDR color contract; HDR and unknown-color previews fail explicitly. `ComparisonPreviewController` runs both local decodes away from the UI thread, cancels stale seeks, and publishes copied images through a bounded, thread-safe `QQuickImageProvider`. QML still uses `QMediaPlayer` for continuous synchronized playback; stepping displays the direct decoded stills and follows actual adjacent PTS values, including VFR intervals.

Input I/O is restricted to local regular files and the `file` protocol. Cancellation uses a stop token, interrupt callbacks and boundary checks. FFmpeg errors carry both operation text and the native error code. The current decoder is software-only; CUDA frame surfaces and transfers will be separate from CPU planes.

`remux` copies existing compressed streams and metadata; it does not perform interpolation or video encoding. Timestamp rescaling occurs after mux header creation, when final output time bases are known. Incompatible streams fail visibly. Output is written under a unique same-directory reservation, finalized and structurally probed, then atomically published without replacement on Windows. Exceptions/cancellation clean up the temporary file. For interpolated queue jobs, committed segment checkpoints can be resumed after a process kill. If the final output was already atomically published but the SQLite completion commit was interrupted, startup hashes the existing file under a read lease and adopts it only when it matches the persisted publication proof and result structure; altered or unproven files remain untouched and interrupted.

`VideoMuxWriter` accepts owned CPU pixel planes at explicit rational timestamps/durations, encodes the selected video and copies the reference input's other streams. The time base must represent submitted times exactly; overlapping or unknown timestamps are rejected. Encoder output is drained in DTS order, with submitted PTS/duration associations retained through reordering. The pending association table is capped at 1024 entries. A separate input handle pumps auxiliary packets according to source-video DTS so they need not be retained for the entire job. This implementation prioritizes correctness; shared-demux and GPU-surface optimizations remain required.

Encoding copies color properties to both frames and encoder context, rebuilds available static HDR frame metadata and retains codec-independent stream side data. Pre-publication checks verify stream presence, output bit depth and known color tags. Implicit precision reduction is rejected; HDR bit-depth reduction and RGB/YUV color transforms require the future validated color pipeline. Basic same-color pixel layout changes use libswscale. The selected encoder must open successfully; a registered encoder name is not a hardware capability claim. See `docs/development/ENCODING.md` for the current NVENC incompatibility.

## Implemented interpolation pipeline

`core/pipeline/video_pipeline` now joins adjacent decoded frames, the integer-index rational CFR clock, SDR conversion, conservative scene analysis, real asynchronous ONNX CUDA inference and the frame writer. It owns no UI state. Inputs remain bounded to adjacent frames and one pending output; exclusive GPU output buffers can be reclaimed only after all immutable references have gone. Source-coincident frames bypass inference. Held cut/duplicate/abnormal pairs are separately reported.

Frame adaptation is selected through `interpolation::ModelAdapterRegistry`. The built-in `rife-sdr-v1` adapter owns input-profile validation, source preprocessing, the RGB scene-analysis view and output color restoration; the pipeline calls those methods instead of naming the RIFE color functions directly. A model descriptor can declare an adapter ID/version, and schema-v2 numerical evidence is rejected when it names a different adapter. Adapter implementations are application-owned C++ code; a model pack cannot execute code or register itself. Queued jobs, saved processing identities and checkpoint manifests bind the selected adapter ID/version; legacy checkpoints are treated as the built-in adapter only. The current public tensor boundary remains FP32 NCHW RGB, dynamic timestep and 64-pixel spatial padding. Runtime plugin discovery, desktop eligibility and non-RIFE tensor shapes remain future work.

The last output duration preserves the source's exclusive end. Full output re-decode, frame-count/PTS checks, copied-audio boundaries and color checks run inside the writer's prepublication callback. The `auto` encoder policy tests actual NVENC initialization and records the specific software fallback reason. Explicit codec requests stay strict. AAC priming/Matroska CodecDelay and final-packet presentation duration are preserved, with decoded-PCM regression evidence. See [pipeline contracts](../development/PIPELINE.md).

## Required next contracts

- GPU-surface encoder submission, source-shared demux, comprehensive color conversions, HDR preview/display conversion and full compatibility/fault coverage for the implemented CPU-frame writer.
- Expand the integrated native CUDA numerical/operator and video-reference tests to the full resolution/content/color matrix, plus TensorRT and qualified model presets.
- Extend the checksum-bound RIFE v2 pack schema into a trusted multi-family model registry, with separately reviewed weight rights, qualified quality profiles and model/update versioning.
- Add a separate temporal video-restoration contract and pipeline stage. Do not extend the two-frame/timestep interpolation request to represent restoration. A restoration model must declare task, temporal window, placement relative to RIFE, scaling, accepted color profiles, workspace/memory requirements, and weight provenance/redistribution terms. Keep video pixels, settings, inference and reports local.
- A bounded scheduler with explicit buffer ownership and backpressure across decode, preprocessing, quality, inference, postprocessing and encode stages.
- Persistent task configuration/progress and output-segment checkpoints bound to source/model/adapter/runtime identity. Queue/pipeline integration, hash and media verification, explicit resume, and stream-copy assembly are implemented. Process-crash tests cover active partial segments, a complete frame prefix interrupted before assembly and published-output adoption. Legacy schema-v1 checkpoints map only to the built-in RIFE SDR adapter; the SQLite manifest table migrates transactionally while retaining old records. See [the checkpoint contract and remaining gates](SEGMENT_CHECKPOINTS.md); broad legacy-database migration, multi-hour coverage, fault injection at all crash boundaries, orphan reconciliation and wider hardware/content qualification remain open.
- A color contract defining transfer/primaries/range/matrix, precision, HDR side data and conversion policy at every stage. Do not equate retained tags with a validated HDR neural processing pipeline.

## Validation mapping

`tests/unit/` covers rational scheduling, task-store semantics, frame ownership and stop behavior. `tests/integration/media_test.py` generates synthetic video/audio/subtitle/chapter fixtures and compares native operations to separately invoked FFmpeg tools. Tests and their limits are documented in `docs/development/FFMPEG.md`. Full SRS and release validation remain open.

The CUDA driver module separately owns context/stream/buffer lifetime. The ONNX adapter uses a bounded single-worker queue and prebound device outputs; its public interface carries no vendor API types. Model loading checks bounded files, hashes and tensor shapes. Runtime dependencies, small-profile numerical/operator evidence and the remaining hardware/resolution matrix are detailed in `docs/development/GPU.md`; CPU export qualification is deliberately scoped in `docs/development/RIFE_MODELS.md`.

The media service exposes source-profile encoder context probes separately from FFmpeg's encoder registry. Studio uses this at import to select NVENC or the first source-compatible software encoder among H.264, HEVC and AV1; the diagnostic CLI reports each candidate. Context initialization is only a preflight signal. Encoded-frame success is still established by the real job's finalized-output validation. The pipeline separately prefers CUDA/NVDEC for source decode when the selected CUDA device and decoder can negotiate hardware frames, transfers those frames to owned host storage for the current RIFE preprocessing path, and falls back to software when setup or pixel-format negotiation cannot start. The `media-scan --decode` diagnostic reports the actual path and fallback reason; later transfer errors fail visibly because restarting after callback delivery could duplicate pipeline work.
