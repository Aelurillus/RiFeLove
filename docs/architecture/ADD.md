# Architecture design document

Version 0.2 status reconciliation, 2026-10-31. This document distinguishes implemented core boundaries, legacy interfaces, executed evidence and remaining product work. The complete [Master Plan](../MASTER_PLAN.md) and [SRS](../SRS.md) remain the acceptance baseline, including the user's explicit native-Windows/desktop-only amendment. Pending P0/P1/P2 desktop capabilities have not been removed or reclassified as optional deliverables.

## Layering

The product client is the native Windows desktop in `apps/native_desktop`, using Win32 controls, Direct2D and DirectWrite. It submits work through application services; the shared core schedules rational presentation times and coordinates media, quality, interpolation and GPU resources. Vendor contexts belong to those services/backends, not the visual surface. The current stack remains C++20, FFmpeg, CUDA, RIFE, ONNX Runtime CUDA/TensorRT, SQLite and CMake/Ninja, with local logging and native tests. The supported build/package has no Qt/QML or end-user CLI dependency. Python/PyTorch are development/export/reference tools only.

`apps/desktop`, `StudioController`, `QueueController`, `QAbstractListModel`, QML pages and their Qt workers are legacy implementation references. Likewise `apps/cli` calls public C++ media/pipeline APIs only as optional internal developer tooling; it is not a product frontend or bundled executable. Their tests remain useful for the covered service contracts but cannot close native workflow gates. The current native client has Studio, queue/history, a bounded local Model Center and comparison with muted synchronized preview and exact stepping. Full model lifecycle, playback/comparison qualification including audio, profile lifecycle, accessibility and current-package acceptance remain partial/pending.

RIFE pack schema v2 verifies ONNX, license, source-manifest and validation-report hashes and cross-checks declared model/profile/backend evidence. Legacy v1 packs remain distinguishable as lacking sidecar hash binding. Hashes prove local consistency, not publisher authenticity, perceptual quality or redistribution rights. The native Model Center registers local directories without copying weights, verifies/revalidates sidecars, persists eligible per-family defaults and unregisters without deleting files. Fixture tests cover those bounded operations and invalid-default/corruption behavior. Large-pack background progress/cancellation, trusted provenance, managed version/cache/rollback, wider accessibility and full packaged lifecycle acceptance remain open; see [the native model guide](../user-guide/NATIVE_MODEL_CENTER.zh-CN.md).

`application::TaskQueue` owns configured-task execution and live database ownership. The common executor admits one job at a time per process and protects source bytes with a native read lease. `task_details` stores versioned configuration/identity/progress/result payloads beside the task state machine. Batch insertion and state/result publication are transactional; progress is throttled. Jobs pin model descriptors when queued and retain checked source/model identity after preparation. `ImportService` performs bounded local file/folder discovery, path deduplication, output allocation, probe/color eligibility checks and stop-aware atomic enqueue. Recovery requires the OS ownership lock, marks active configured work interrupted, and preserves history. Configured jobs write validated, hashed, video-only checkpoints; resume decodes source context from the beginning, skips the committed output prefix, then assembles the validated result. See [queue contracts](../development/QUEUE.md). Named JSON profiles and their schema/path checks have legacy Qt evidence; complete native profile lifecycle, quality-ranked presets, history pagination and multi-hour/fault acceptance remain open.

## Offline runtime and model boundary

Video I/O, inference, model verification, settings, task databases, logs, caches and reports stay on the local machine. The runtime does not fetch weights, query a cloud model catalog, upload media/telemetry, check remote updates or contact creator-platform accounts. Model packs are acquired separately and manually imported/discovered as local files; missing weights fail with a useful local path. Pack metadata is declarative and cannot install executable adapters. A future model lifecycle service must retain version/integrity/rollback and provenance requirements while honoring the current offline/manual acquisition policy.

Alibaba Cloud OSS is disabled and is not a fallback for missing local files. The previously authorized Storj major-release backup is unconfigured/disabled and outside application runtime; any future separately verified backup is limited to reviewed release artifacts, excluding user media/history, secrets and weights with unresolved rights. Developer source-repository publication and explicit build-time dependency acquisition are separate operations, not runtime network dependencies. The default local build uses existing pinned dependency caches. Clean-machine offline/package qualification remains required.

## Implemented media contract

`MediaEngine::probe` returns stream/container/chapter metadata in standard C++ values. `decodeVideo` yields `DecodedFrame` objects with rational PTS, optional duration, native pixel planes, color and reference-counted ownership. Retained frames remain valid after decoder closure. The interface does not require callers to include FFmpeg headers. Missing timestamps are explicit, and observed cadence accounts for input-time-base quantization.

`MediaEngine::decodeFrameNearTime` supplies the native comparison's frame primitive: seek to a preceding key frame, decode in presentation order, return the nearest timestamped frame, adjacent PTS and a bounded owned RGBA image. Conversion is limited to the tagged SDR contract; HDR and unknown color fail explicitly. `ComparisonPreviewController`, `QQuickImageProvider` and synchronized `QMediaPlayer` playback belong to the legacy Qt viewer. The current native integration uses the modeless comparison and muted shared-clock preview described below; audio playback, artifact navigation and full playback qualification remain pending.

## Native layout and synchronized comparison

`NativeLayout` uses a single settings column below 760 DIP client width, a compact navigation rail and stacked export settings. The main minimum width is 480 DIP, clamped to the monitor work area. Fixed task actions remain outside the scrolled settings surface; the narrow layout gives progress/status its own row. Child-control subclasses route the wheel to settings over edits, buttons and closed combos without modifying combo values; an open combo retains its wheel input. Logical focus traversal includes clipped-but-eligible settings, scrolls them into view before assigning focus and skips disabled/collapsed controls. An explicit scroll hint and top/bottom scroll commands make lower output/restoration/exposure settings reachable.

`native_output_target.hpp` resolves compatible x2 targets on the source aspect-ratio lattice, requiring even dimensions and the encoder dimension limit. It supports 4:3, portrait and ultrawide inputs without forcing 16:9 or stretching. When the exact named short-edge tier is unavailable, the label says approximate and displays actual dimensions; source dimensions that are unavailable are labeled as waiting for import, not 0-by-0. This coded-pixel ratio policy does not establish SAR/display-aspect calibration.

`NativeComparisonWindow` is one reusable modeless Win32 window owned by `NativeApp`. A persistent `std::jthread` performs local probe/software decode outside the UI thread. Requests carry a generation and stop source; replacement requests coalesce, cancellation is cooperative and only the current generation can publish. Closing cancels and destroys controls without synchronously joining decode on the window thread; the owning object's destruction eventually joins its worker. Reopening reuses the owner while stale completions are ignored. Images are owned RGBA converted to BGRA for native drawing and fitted proportionally to the current two panels.

The window chooses source and result locally and aligns their independently verified time origins at the same relative presentation time. It accepts rational time or seconds with up to nine decimal places, a slider, and previous/next actual output PTS rather than a nominal FPS increment. If stream start PTS is absent, the first decoded frame must supply a verified original PTS; missing/recovered origin is rejected instead of assuming zero. A predecessor missing after keyframe seeking may require a cancellable scan from the beginning; long-video stepping latency is not qualified.

Muted synchronized playback uses one `steady_clock` anchor and rational relative-time requests for both videos, capped at 30 preview requests per second. The worker returns one complete source/result pair for atomic UI publication. A busy decoder is allowed to finish instead of being cancelled on every playback tick; the next request catches up to the shared clock, skipping preview frames when decoding is slow. The last valid pair remains visible during playback decode. Pause invalidates pending playback generations and freezes the last published pair; seeking, stepping and file selection pause transport. Known common duration bounds playback, unknown duration uses decoded stream boundaries, and playback can restart at EOF. Closing or externally destroying the window stops its timers and invalidates pending work. Space toggles transport outside text fields, with key-repeat suppression. Exact stepping remains available independently of the preview rate.

There is no audio playback or audio clock. Preview is not guaranteed to present every encoded frame or sustain real-time speed on representative long-GOP/high-resolution inputs; each request still uses the seek/decode primitive above. Any non-identity display matrix, including zero-angle reflection/translation, and explicit nonzero rotation is rejected until correct display-transform handling exists. The decoded preview carries FFmpeg’s per-frame sample aspect ratio when known; each pane fits its display aspect independently and identifies an unknown ratio rather than inventing one. Broader changing-SAR and real-media qualification, HDR/unknown-color conversion, full VFR/display/content coverage and artifact navigation remain open.

## Media I/O and publication

Input I/O is restricted to local regular files and the `file` protocol. Cancellation uses a stop token, interrupt callbacks and boundary checks. FFmpeg errors carry operation text and the native error code. Source decode prefers CUDA/NVDEC when setup/format negotiation succeeds, then transfers surfaces into owned host planes for current preprocessing; setup failure falls back before callbacks, while later transfer failure stops visibly. The public decoded-frame contract remains owned CPU planes. Zero-copy decode-to-inference-to-encode is not implemented or claimed.

`remux` copies existing compressed streams and metadata; it does not perform interpolation or video encoding. Timestamp rescaling occurs after mux header creation, when final output time bases are known. Incompatible streams fail visibly. Output is written under a unique same-directory reservation, finalized and structurally probed, then atomically published without replacement on Windows. Exceptions/cancellation clean up the temporary file. For interpolated queue jobs, committed segment checkpoints can be resumed after a process kill. If the final output was already atomically published but the SQLite completion commit was interrupted, startup hashes the existing file under a read lease and adopts it only when it matches the persisted publication proof and result structure; altered or unproven files remain untouched and interrupted.

`VideoMuxWriter` accepts owned CPU pixel planes at explicit rational timestamps/durations, encodes the selected video and copies the reference input's other streams. The time base must represent submitted times exactly; overlapping or unknown timestamps are rejected. Encoder output is drained in DTS order, with submitted PTS/duration associations retained through reordering. The pending association table is capped at 1024 entries. A separate input handle pumps auxiliary packets according to source-video DTS so they need not be retained for the entire job. This implementation prioritizes correctness; shared-demux and GPU-surface optimizations remain required.

Encoding copies color properties to frames and encoder context, rebuilds available static HDR frame metadata and retains codec-independent stream side data. Prepublication checks verify streams, output bit depth and known color tags. Implicit precision reduction is rejected; retained HDR metadata does not qualify HDR neural processing or display conversion. Tagged SDR conversion uses libswscale and the model adapter's explicit profile. The selected encoder must open successfully; registration alone is not a hardware claim. The compatible local SDK has bounded GTX 1660 SUPER NVENC/NVDEC evidence; older SDK/driver incompatibility records remain historical. Full device/codec/color and packaged-runtime acceptance are open.

## Implemented interpolation pipeline

`core/pipeline/video_pipeline` joins decoded frames, an integer-index rational CFR clock, SDR conversion, conservative scene analysis, asynchronous interpolation and the frame writer. It owns no UI state. Ordinary interpolation retains adjacent source frames and one pending output; optional exposure synthesis retains the entire timestamp-defined shutter window under a separate budget. GPU outputs are reclaimed only after immutable references are gone. Ordinary source-coincident output bypasses inference; exposure output may integrate neighboring samples even when its center coincides with a source frame. Cut/duplicate/abnormal holds and exposure fallback are reported separately.

Frame adaptation is selected through `interpolation::ModelAdapterRegistry`. The built-in `rife-sdr-v1` adapter owns input-profile validation, source preprocessing, the RGB scene-analysis view and output color restoration; the pipeline calls those methods instead of naming the RIFE color functions directly. A model descriptor can declare an adapter ID/version, and schema-v2 numerical evidence is rejected when it names a different adapter. Adapter implementations are application-owned C++ code; a model pack cannot execute code or register itself. Queued jobs, saved processing identities and checkpoint manifests bind the selected adapter ID/version; legacy checkpoints are treated as the built-in adapter only. The current public tensor boundary remains FP32 NCHW RGB, dynamic timestep and 64-pixel spatial padding. Runtime plugin discovery, desktop eligibility and non-RIFE tensor shapes remain future work.

The last output duration preserves the source's exclusive end. Full output re-decode, frame-count/PTS checks, copied-audio boundaries and color checks run inside the writer's prepublication callback. The `auto` encoder policy tests actual NVENC initialization and records the specific software fallback reason. Explicit codec requests stay strict. AAC priming/Matroska CodecDelay and final-packet presentation duration are preserved, with decoded-PCM regression evidence. See [pipeline contracts](../development/PIPELINE.md).

## Dynamic exposure and local platform copies

Natural motion exposure is separate from restoration and is optional. Product settings expose enable/disable, shutter angle 0..360 degrees and sample count 1..16; effective exposure requires a positive shutter and multiple samples. Native controls and per-preset state exist; final current-build UI/package acceptance must verify those controls actually reach job configuration/output. At output center `t` and target rational rate `r`, the production planner covers the full interval `[t - angle/(720*r), t + angle/(720*r)]`, synthesizes midpoint samples and integrates in linear SDR light. Actual decoded PTS, not a nominal source-FPS estimate, determine brackets and lookahead.

A source deque preserves the next shutter's left bracket and waits for complete future coverage. Edge holds are allowed only at the true source start/EOF. A cut, duplicate or abnormal pair anywhere in the full interval causes an explicit center/left fallback, even between sample positions. Prepared source-window floats are bounded by `min(4096, hostFloatBufferLimit / preparedFrameBytes)` frames, with a default 512 MiB float budget; decoder storage, accumulator, sample/output and restoration buffers are additional. A window that cannot fit fails rather than silently counting a sharp frame as successful blur. Cancellation/failure preserves non-replacing publication semantics.

`PipelineResult` and serialized `motionBlur` / report `qualityDiagnostics.motionBlur` distinguish integrated output, fallback output/reasons, true edge holds and peak prepared-window use. For newly processed frames, `blurredFrames + fallbackFrames == processedFrames`; reused checkpoint output is excluded. Enabled job/checkpoint serialization binds algorithm version 2, preventing reuse of segments from the former four-frame exposure implementation.

High-rate local masters (including 240/300/360/480/600 FPS) and platform copies are independent exports. Native presets offer local YouTube/Bilibili/Douyin 60 FPS, Douyin 30 FPS and historical/experimental Bilibili 120 FPS settings. `NativeApp::applyExportControls` computes single-file platform settings; batch `ImportService` computes them after probing each source and resolving its requested 1440p/2160p target. Both use `application::platformExportSettings` with the exact target rational rate, source dimensions, selected model scale and optional explicit output size. The helper buckets by actual output short edge, so portrait 1080x1920 does not accidentally enter the 1440p bitrate tier. Only policy rounding affects bitrate/GOP; the job's exact target FPS is retained. The helper computes encoding settings without resizing/cropping frames.

These presets suggest local rate/container/bitrate/GOP choices, not an upload or a platform playback entitlement. The output is still subject to actual encoder, source color, auxiliary-stream/container and final timing validation. The preset does not promise AAC conversion, resolution/crop changes or avoidance of platform transcoding. See [platform export policy and source distinctions](PLATFORM_EXPORT.md). A 60 FPS exposure-integrated file does not retain 240/300+ FPS native temporal samples, and no platform's "240 FPS-like" appearance has been verified.

## Video restoration boundary

`restoration::IVideoRestorationBackend` is a separate asynchronous interface; it does not overload RIFE's two-frame/timestep request. Registry/request/result validation checks task, placement, SDR profile, timestamped temporal context, center PTS/duration, color and scale. Local pack verification checks graph/sidecar hashes, license/source/validation declarations and confined paths. Legacy Qt Model Center catalog evidence is separate from pending native catalog/lifecycle acceptance.

The core contains a source-rate temporal-denoise boundary and an optional output-rate image-restoration stage after interpolation. The latter uses FP32 NCHW RGB, dynamic shapes, overlap tiling and TensorRT EP with CUDA fallback; cache identity is separated from RIFE. Native denoise/restoration choices and local model identity wiring exist, but code presence is not acceptance of every combined model/blur/resume path. Serialized job/checkpoint identity pins the applicable local descriptor and runtime choices. Temporal denoise does not by itself implement compression cleanup, detail reconstruction or general deblur.

Historical synthetic super-resolution evidence produced validated 1024x576/60 FPS from a 256x144 clip, measured 0.44 end-to-end output FPS on the development GTX 1660 SUPER in the CUDA run, and reduced restoration time from 12.15 s to 2.62 s using TensorRT. Warm-cache execution took 9.0 s, cold setup about 100 s; six-frame TensorRT/CUDA comparison was backend parity only. These figures do not qualify real-content quality, temporal stability or representative performance. The Real-ESRGAN x4plus evaluation pack stays local while redistribution terms are unresolved; pack hashes do not establish rights or quality.

Content-adaptive restoration remains partial. The source-rate temporal stage now optionally estimates additive Gaussian noise and drives FastDVDnet conditioning through exact-PTS smoothing/cut reset. `PipelineSettings::automaticTemporalDenoise` defaults absent; schema 9 persists the opt-in and binds its versioned software-decode/replay policy to job/checkpoint identity. Native controls require an eligible FastDVDnet and explicit confirmation, explain grain/detail loss and the software-decode/replay cost, and clear the opt-in when the model is removed. With FastDVDnet selected and automatic mode off, the current native path still denoises at fixed sigma 25; disabling automatic estimation is not bypassing the selected model. With no temporal model selected, the stage is off. The native queue-serialization fixture covers the model plus enabled settings crossing the saved-job boundary.

Automatic mode forces software source decoding; selected GPU inference remains in use. Resume replays original source PTS and temporal context from the beginning, reusing only verified committed output rather than fast-seeking directly to the checkpoint. Synthetic real-backend evidence includes a demonstrated intended-film-grain false positive even at confidence 1. The mode remains experimental/default off, not general compression repair, lost-detail recovery or deblur. See [the automatic Gaussian architecture and evidence](AUTOMATIC_GAUSSIAN_DENOISE.md). General compression/detail estimators, independent relative-adjustment UI, real-video perceptual/temporal quality and representative-resolution/long-video recovery acceptance remain open. Natural exposure is an independently implemented temporal-integration feature, not evidence that these restoration requirements are complete.

## Required next contracts

- GPU-surface encoder submission, source-shared demux, comprehensive color conversions, HDR preview/display conversion and full compatibility/fault coverage for the implemented CPU-frame writer.
- Expand the integrated native CUDA numerical/operator and video-reference tests to the full resolution/content/color matrix, plus TensorRT and qualified model presets.
- Extend the checksum-bound RIFE v2 pack schema into a trusted multi-family model registry, with separately reviewed weight rights, qualified quality profiles and model/update versioning.
- Complete and qualify temporal restoration for denoising, deblurring, compression cleanup and detail reconstruction; the existing temporal-denoise boundary is only a partial implementation. Add content-adaptive estimation/control integration, bounded memory/OOM policy, cancellation/resume behavior and realistic validation. Each model declares task, temporal window, placement, scaling, color, workspace/memory and weight provenance/rights. Keep pixels, settings, inference and reports local.
- A bounded scheduler with explicit buffer ownership and backpressure across decode, preprocessing, quality, inference, postprocessing and encode stages.
- Persistent task configuration/progress and output-segment checkpoints bound to source/model/adapter/runtime identity. Queue/pipeline integration, hash and media verification, explicit resume, and stream-copy assembly are implemented. Process-crash tests cover active partial segments, a complete frame prefix interrupted before assembly and published-output adoption. Legacy schema-v1 checkpoints map only to the built-in RIFE SDR adapter; the SQLite manifest table migrates transactionally while retaining old records. See [the checkpoint contract and remaining gates](SEGMENT_CHECKPOINTS.md); broad legacy-database migration, multi-hour coverage, fault injection at all crash boundaries, orphan reconciliation and wider hardware/content qualification remain open.
- A color contract defining transfer/primaries/range/matrix, precision, HDR side data and conversion policy at every stage. Do not equate retained tags with a validated HDR neural processing pipeline.

## Validation mapping

`tests/unit/` covers rational scheduling, task-store semantics, frame ownership and stop behavior. `tests/integration/media_test.py` generates synthetic video/audio/subtitle/chapter fixtures and compares native operations to separately invoked FFmpeg tools. Tests and their limits are documented in `docs/development/FFMPEG.md`. Full SRS and release validation remain open.

Native evidence executed on 2026-10-31: Release desktop/controls/processing targets built, `NativeDesktop.Controls` passed 1/1, and the native processing test passed model-center/settings/comparison-state fixtures. Real HWND tests cover 480, 600, 700, 790, 800 and 850 DIP outer widths, logical focus/scroll, child-control wheel routing, fixed actions, non-16:9 output targets and portrait/4:3 shared platform settings. Layout calculations cover 100–200% scaling. The explicit `--comparison` run decoded the small local tagged SDR source/result, checked same-relative-time selection, adjacent actual PTS, slider/EOF and actual probed zero-angle reflection/translation rejection. Fake-loader checks cover coalescing, cancellation, stale completions and close/reopen. Images from real HWND Direct2D rendering on an isolated desktop were reviewed under `work/native-ui-e2e`; physical-screen appearance, multi-monitor DPI switching and broad accessibility remain unaccepted.

The subsequent synchronized-preview change rebuilt `rifelove-native-processing-test` and passed its loader regressions for different/negative origins, 30/120 FPS, pause freezing, slow-decode cancellation, no late frames, exact stepping, known/unknown-duration boundaries, EOF replay, failure stopping and close/reopen. Comparison transport geometry also passed at 480/640/1000 DIP outer widths. A separate real `--comparison` run used two-second, 192x128 synthetic tagged SDR files at 30/120 FPS in `out/native-comparison-playback-20261031`; it checked playback advancement, paired time selection, pause freezing and return to frame stepping, with playing/paused/narrow images inspected. The higher-rate fixture repeats frames and is not neural interpolation. Real-media EOF positioning and fixture-driven playback EOF are distinct evidence. These bounded tests do not accept audio, full-rate high-FPS playback, real-content visual quality, representative throughput, SAR correctness, long-video stability or a coherent current package.

Executed on 2026-10-31: the local Release `MotionBlurSampling.*`, `MotionBlurExposure.*` and `MotionBlurPipeline.*` checks passed 17/17, including five real-`interpolateVideo` integration tests. Their shared fixture is `tests/integration/motion_blur_pipeline_test.hpp`, registered by `tests/unit/motion_blur_test.cpp`. Ten 240/300/360/480/600-to-60 and 60000/1001 combinations produce 12 frames each, assert zero fallback on continuous motion, verify accounting/peak bounds and require actual pixels to differ from center-only output. Additional production tests cover true source-edge EOF draining, cut fallback without scene mixing, insufficient full-window budget and cancellation with no published/partial output. The ignored local evidence file is `build/windows-release/motion-blur-regression.xml`.

Those tests use tiny lossless tagged SDR clips and a deterministic linear backend with real CUDA buffers; they qualify production orchestration/exposure behavior, not RIFE/TensorRT perceptual quality, broad performance, the native UI/package or platform uploads. Actual Matroska source PTS include millisecond quantization. Planner tests separately cover nonzero-origin VFR, shutter/sample combinations and unsampled quality barriers. HDR exposure, full resolution/length/hardware coverage, actual creator-account upload/transcode/playback checks and product release gates remain pending. Do not infer these from newly added but unexecuted tests or from an older Qt result.

The CUDA driver module separately owns context/stream/buffer lifetime. The ONNX adapter uses a bounded single-worker queue and prebound device outputs; its public interface carries no vendor API types. Model loading checks bounded files, hashes and tensor shapes. Runtime dependencies, small-profile numerical/operator evidence and the remaining hardware/resolution matrix are detailed in `docs/development/GPU.md`; CPU export qualification is deliberately scoped in `docs/development/RIFE_MODELS.md`.

The media service exposes source-profile encoder context probes separately from FFmpeg's registry. Application preflight can choose NVENC or a source-compatible software path among H.264, HEVC and AV1; optional internal CLI diagnostics report candidates but are not product features. Context initialization is only preflight; encoded-frame success comes from finalized-output validation. CUDA/NVDEC setup and actual decode/fallback are reported independently. Later transfer failures stop visibly because restarting after callbacks could duplicate work.
