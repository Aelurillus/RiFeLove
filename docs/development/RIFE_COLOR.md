# Initial RIFE SDR color contract

`prepareRifeSdr` and `restoreRifeSdr` form a CPU preprocessing/postprocessing boundary independent of the inference backend. This is a tested subset of the complete color pipeline, not HDR or complete SDR format acceptance.

The input must have owned, valid pixel planes with positive dimensions <=8192, 8- or 10-bit integer components, explicit BT.709 or BT.470BG/SMPTE 170M primaries, and an explicit BT.709, SMPTE 170M or sRGB transfer. RGB requires `gbr` matrix/full range. YUV accepts BT.709 matrix with BT.709 primaries, or BT.601-family `smpte170m`/`bt470bg` matrix with matching legacy primaries; range must be explicitly full or limited. Hardware surfaces, alpha, palette, unknown metadata, other depths and HDR are rejected. The adapter reports the matching `bt709-sdr8`, `bt470bg-sdr8`, `bt709-sdr10` or `bt470bg-sdr10` model profile. These are normalized **nonlinear RGB** values in the source gamut, not linear-light/tone-mapped values.

When the container stream and decoded frame disagree only within the BT.601 matrix aliases (`smpte170m`/`bt470bg`) and BT.709/SMPTE 170M SDR transfer tags, the decoder uses the explicit container stream tags as the output metadata contract only if pixel layout, bit depth, primaries and range match and both descriptions pass the SDR checks. This covers files whose H.264 VUI and MP4 color description conflict while remaining inside this qualified SDR family. Other mismatches, HDR side data, unknown tags and range differences are not normalized.

libswscale is configured with explicit BT.709 or BT.601-family coefficients and source/destination ranges based on the tags. An RGB48 intermediate avoids an extra RGB8 quantization before FP32 normalization. The contiguous batch-1 NCHW buffer is padded to a multiple of 64 by repeating the last row/column. The configured float-buffer limit is checked before allocation; this limit does not cover all temporary buffers or GPU inference memory. Cancellation is checked around conversion and between rows.

Postprocessing validates finite normalized pixels, crops to the original dimensions and converts through RGB48 back to the original 8- or 10-bit layout/range/matrix. The returned frame owns its planes independently. Presentation timestamps/durations remain the timeline's responsibility. This path does not add HDR qualification to a model or silently infer missing color information.

Nine unit cases check RGB channel order/edge padding/crop/ownership, 8-bit and 10-bit limited-range levels, BT.709 and BT.601-family color coefficients, profile mapping, source-tag preservation, the constrained container/VUI conflict rule and rejection of unknown color/HDR/depth/nonfinite pixels/budget/cancellation. The desktop workflow runs a tagged BT.470BG/SMPTE 170M 8-bit source through CUDA RIFE and verifies output color tags and audio. 10-bit conversion is currently covered by synthetic CPU round trips; real-content 10-bit RIFE visual review, broader chroma formats/positions, gamut/clipping policies and GPU conversion remain required.
