## 当前决议

- 面向 Windows 10/11 x64 与 NVIDIA GPU，用户交付为桌面应用；主界面和发行包不使用 Qt/QML，也不交付 CLI。
- 原生桌面以 Win32、Direct2D 和 DirectWrite 为实施方向。媒体、时间轴、模型、推理和任务服务继续通过独立 C++ 接口接入。
- 阿里云 OSS 不再用于该项目。源视频、模型推理、任务、设置、日志和检查点保留在本机。此前约定的大版本备份仅在发布内容和许可具备条件后使用 Storj；不上传用户素材或本地任务数据。
- 交付需要实际可启动的 EXE、所需运行库、选定模型、默认设置、完整文档和最终安装/卸载方案。运行时不依赖 Python。
- 主模型负责规划和协调；具体实现、构建、测试、评审和清理由子代理完成。

## 阶段 B：高帧率、平台副本与动态曝光

- [ ] 任意目标帧率仍使用有理数时间轴；验证 360/480 FPS、分数帧率、VFR、最终帧、音轨和输出时长。
- [ ] 60 FPS 动态曝光通过对每个输出时刻的多个插值时间样本进行线性光合成实现；输出帧数和 PTS 由最终目标帧率决定。
- [ ] 曝光采样跨源帧边界时使用正确邻帧；切镜、异常运动和重复帧不得跨质量边界混合。视频开头/结尾、窗口不足和取消有明确回退。
- [ ] 默认关闭动态曝光；关闭或零快门保持原处理路径。任务配置与检查点身份包含相关设置。
- [ ] B 站、抖音和 YouTube 有适用的本地导出预设，并明确平台可能重新编码或限制播放帧率。60 FPS 曝光副本可改善运动观感，但不宣称具有真实 144/240 FPS 的时间分辨率。
- [ ] 采样和缓存有界；记录实际推理次数、端到端速度和显存占用，避免把输出 FPS 当成处理速度。

**阶段证据：** 匀速运动和切镜素材、源帧重合及跨区间测试、23.976/29.97/VFR 素材、独立帧数/PTS/时长/音轨检查和实际 GPU 视频运行。单元测试不能代替完整视频验收。

## 阶段 D：模型比较、超分和清理

- [ ] 比较可用插帧与超分候选的来源、代码及权重许可、数值正确性、真实素材画质、时间一致性、耗时和显存。以相同素材与设置记录本机结果；不同素材可能有不同优胜者。
- [ ] 选定一个默认插帧模型和一个默认超分模型；需要独立去模糊时保留其明确用途，不把自然动态模糊误认为去模糊模型。
- [ ] 支持约 1080p 到 1440p 和 2160p 的明确目标尺寸，记录模型倍率和必要的重采样；验证尺寸、色彩、时间轴与性能。
- [ ] 对插帧与超分分别分析解码、色彩变换、推理、显存传输、编码和模型初始化耗时；在真实 GPU 上优化缓冲复用、分块和并行调度，并记录前后性能与峰值显存。仅在数值和画质验收通过后启用 FP16 等精度优化。
- [ ] 删除确定冗余的模型缓存前，验证保留模型可运行并检查队列/检查点对旧路径和哈希的引用。只清理授权范围内的模型与重复缓存，保留用户视频、结果和任务数据。
- [ ] 模型包记录版本、SHA-256、来源、许可与验证范围；未确认权重再分发条件的模型仅供本机使用，不上传发布。
