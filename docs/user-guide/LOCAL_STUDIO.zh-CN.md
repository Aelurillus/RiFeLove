# 本地插帧工作室

这是正在开发的桌面版本，完整产品功能仍按 [开发任务清单](../DEVELOPMENT_PLAN.md) 推进。Studio 支持单个视频处理，任务队列支持批量文件和文件夹。本地界面不会上传视频或自动下载模型。

1. 按照 [桌面构建指南](../development/DESKTOP.md) 完成本地构建并启动程序。
2. 点击“选择文件”，或把一个视频拖进导入区域。程序会读取视频信息并检测 NVIDIA GPU。
3. 选择目标帧率。可以输入 `60`、`144` 或 `60000/1001` 等分数值。目标帧率决定生成的视频帧率，界面显示的“处理 FPS”表示本机实际处理速度。进度区会按源视频声明时长估算输出帧总数和剩余时间；这是估值，最终帧数以解码时间轴验证结果为准。工作期间还会显示 RIFE 推理、视频编码、解码和预处理/色彩转换的累计耗时，完成后补上输出验证时间，便于判断慢点位于哪一阶段。
4. 选择输出位置和编码器。默认生成带 `_RifeLove` 的新 MKV 文件；已有文件不会被覆盖。音轨或字幕与目标容器不兼容时，任务会明确报错，请选择适合的容器。
5. 在本地模型区域选择已校验的模型包，以及本机 TensorRT/ONNX Runtime CUDA 运行库目录。本地运行包默认选中 RIFE 4.25，并附带 RIFE 4.26 作为另一项可选模型；这不代表 4.26 画质更好。
6. 点击“开始补帧”。程序会先加载模型，处理完成后重新解码检查输出。通过检查后才发布最终视频。

运行日志只写入本机应用数据目录，不会上传。便携包的桌面日志在 `data/logs/rifelove.jsonl`，CLI 日志在 `%LOCALAPPDATA%/RifeLove/logs/cli.jsonl`；非便携桌面版的日志在 `%LOCALAPPDATA%/RifeLove/logs/rifelove.jsonl`。每个日志文件最多 4 MiB，并保留最近 3 个轮转文件。日志记录阶段、编码器回退、完成和错误详情；FFmpeg 错误有时会包含本地文件名，分享日志前请先检查内容。

当前模型路径支持模型清单声明的 BT.709 与 BT.470BG/SMPTE 170M 8/10-bit SDR，并按视频标记的矩阵处理和保留色彩信息。若 H.264 帧内的 BT.601 系列标签与容器标签只有已支持的矩阵别名或 SDR 传递函数差异，且像素格式、位深、原色和范围一致，程序会统一采用容器标签；其他冲突仍会报错。合成的 96×64 BT.709 10-bit 视频已通过 RIFE 插帧、AV1 软件编码回退和输出色彩/时间轴检查；这不等于真实素材画质验收。HDR、其他位深或色彩标记不明的视频仍不支持，界面会阻止已识别的不支持输入。请勿通过修改标签来假装完成真实色彩转换。

自动编码会先检查 NVIDIA 编码器，并按源视频像素格式选择可用的硬件或软件编码器。本机驱动与 FFmpeg 的 NVENC 接口不兼容，所以 8-bit 视频会回退到软件 H.264；测试中的 10-bit 视频会选择 AV1 软件编码，以保留位深。进度区会明确显示实际编码器（例如“CPU H.264 编码”）和“CUDA RIFE 插帧”。`Function not implemented` 是 NVENC 初始化失败的原因，不代表插帧失败。“处理 FPS”是实际生成速度，不是最终输出帧率；例如 5.1 处理 FPS 表示每秒正在生成约 5 帧，帧数持续增长就代表任务仍在推进。若进度不再增长且任务状态变为“失败”，再查看详情中的最终错误。

Studio 连续 60 秒没有收到新输出帧时，会显示“等待 GPU 输出新帧”及资源竞争提示。这是进度停滞提醒，不代表任务已失败；先检查是否有其他程序占用 GPU。输出只有在处理完成并通过验证后才会发布。

高级编码设置中可以显式选择“NVIDIA H.264（NVENC）”，并使用 VBR + CQ 恒定质量（0–51）。该模式只在当前源视频的 NVENC 编码器预检成功时可开始；本机驱动当前不满足要求，因此应继续使用“自动编码”或可用的软件编码器。CQ 越低通常文件越大；不同编码器的 QP/CRF/CQ 数值不能直接比较。

Studio 和任务队列中的“本机配置”共用一份本地配置列表。可以给常用的目标 FPS、模型与运行库目录、编码器、容器、输出目录和编码参数命名保存，再从任一页面选择并应用。配置支持导入、导出单个版本化 JSON 文件；文件只包含设置和本机文件路径，不复制视频、模型或运行库，也不会上传。导入时会检查格式、参数和路径，并拒绝同名配置；删除配置不会删除这些文件。它保存的是参数组合，不代表画质等级经过验证。

## 批量任务队列

1. 打开左侧“任务队列”，选择多个视频，或选择包含视频的文件夹。可以启用“扫描子文件夹”，也可以把文件或文件夹拖入队列。
2. 选择目标帧率、容器、编码器、本地模型包和 ONNX CUDA 运行库。输出文件夹可以留空，此时使用首个来源文件所在目录。
3. 点击“加入队列”。程序会检查文件和模型支持的色彩格式，跳过重复来源及已知输出，并为每个视频分配不会覆盖已有文件的新名称。当前本地模型清单接受明确标记的 BT.709 与 BT.470BG/SMPTE 170M 8/10-bit SDR；HDR、模型未声明的输入配置、未标记色彩和不可读取文件会显示为跳过原因。
4. 点击“开始队列”。任务依次处理；列表显示状态、模型阶段、处理帧数和实际处理速度。队列使用本机应用数据目录下的 SQLite 数据库，FPS、模型、运行库、输出位置、编码器和容器偏好保存在相邻的本地设置文件中。
5. “暂停”会等待安全检查点并保留当前运行中的任务；“继续”恢复同一工作任务。“停止队列”取消当前任务并保留之后排队的任务。失败任务可重试；异常中断任务可选择新输出名从头重启。

普通暂停/继续会在当前进程内接着处理。任务队列每 256 个输出帧保存一个已验证检查点；若进程异常退出，重新打开软件后可在中断任务上选择“从检查点继续”。若最终视频已发布、但队列状态还没来得及保存，软件会在启动时核对文件大小、SHA-256 和验证记录，并自动恢复为完成；文件或记录不匹配时会保留文件并显示诊断。继续前会核对任务、源文件、模型、运行库和已提交片段，只复用通过校验的数据，并清理该任务目录里未登记的临时或分段文件。尚未生成完整检查点的任务只能从头重启。Studio 单文件工作流目前没有队列式断点续传。关闭处理窗口会提示取消正在进行的工作并等待资源清理。

## 对比预览

完成任务后打开左侧“对比预览”，原片和结果会在本机并排播放。可以切换原片/结果文件、拖动时间轴、同步播放或按输出帧率步进。当前步进按时间戳定位；精确到解码帧和自动跳转伪影位置仍在开发中。页面不会上传视频。
