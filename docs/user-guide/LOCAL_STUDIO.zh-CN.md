# 本地插帧工作室

这是正在开发的桌面版本，完整产品功能仍按 [开发任务清单](../DEVELOPMENT_PLAN.md) 推进。Studio 支持单个视频处理，任务队列支持批量文件和文件夹。本地界面不会上传视频或自动下载模型。

1. 按照 [桌面构建指南](../development/DESKTOP.md) 完成本地构建并启动程序。
2. 点击“选择文件”，或把一个视频拖进导入区域。程序会读取视频信息并检测 NVIDIA GPU。
3. 选择目标帧率。可以输入 `60`、`144` 或 `60000/1001` 等分数值。目标帧率决定生成的视频帧率，界面显示的“处理 FPS”表示本机实际处理速度。
4. 选择输出位置和编码器。默认生成带 `_RifeLove` 的新 MKV 文件；已有文件不会被覆盖。音轨或字幕与目标容器不兼容时，任务会明确报错，请选择适合的容器。
5. 在本地模型区域选择已校验、包含 `model.json` 的模型包，以及已安装的 ONNX Runtime CUDA 运行库目录。目前开发模型为 `rife-4.25-fp32-sdr8-v2`。
6. 点击“开始补帧”。程序会先加载模型，处理完成后重新解码检查输出。通过检查后才发布最终视频。

当前模型路径支持明确标记的 BT.709 与 BT.470BG/SMPTE 170M 8-bit SDR，并按视频标记的矩阵处理和保留色彩信息。HDR、10-bit 或色彩标记不明的视频仍需要后续色彩处理支持，界面会阻止已识别的不支持输入。请勿通过修改标签来假装完成真实色彩转换。

“自动 H.264”优先尝试 GPU 编码；若硬件编码器不能打开，会切换到软件 H.264 并在结果中说明。当前本机的驱动与 FFmpeg NVENC 版本不匹配，实际使用的是软件编码，RIFE 推理仍在 NVIDIA GPU 上运行。

## 批量任务队列

1. 打开左侧“任务队列”，选择多个视频，或选择包含视频的文件夹。可以启用“扫描子文件夹”，也可以把文件或文件夹拖入队列。
2. 选择目标帧率、容器、编码器、本地模型包和 ONNX CUDA 运行库。输出文件夹可以留空，此时使用首个来源文件所在目录。
3. 点击“加入队列”。程序会检查文件和模型支持的色彩格式，跳过重复来源及已知输出，并为每个视频分配不会覆盖已有文件的新名称。当前 RIFE 模型接受明确标记的 BT.709 与 BT.470BG/SMPTE 170M 8-bit SDR；HDR、10-bit、未标记色彩和不可读取文件会显示为跳过原因。
4. 点击“开始队列”。任务依次处理；列表显示状态、模型阶段、处理帧数和实际处理速度。队列使用本机应用数据目录下的 SQLite 数据库，FPS、模型、运行库、输出位置、编码器和容器偏好保存在相邻的本地设置文件中。
5. “暂停”会等待安全检查点并保留当前运行中的任务；“继续”恢复同一工作任务。“停止队列”取消当前任务并保留之后排队的任务。失败任务可重试；异常中断任务可选择新输出名从头重启。

暂停不是断点续传。异常中断后，RifeLove 不会从记忆中的帧号继续拼接；真正的分段断点恢复仍在开发中。关闭处理窗口会提示取消正在进行的工作并等待资源清理。比较预览、模型中心、完整色彩管线、多语言和发行版仍在开发中，尚未把阶段性桌面流程当作最终产品交付。
