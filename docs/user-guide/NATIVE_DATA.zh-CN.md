# Native 本地数据目录

## 安装模式（默认）

Native Win32 客户端通过 Windows 的 Local AppData 已知文件夹定位当前用户的本机数据目录，默认使用 `%LOCALAPPDATA%\RifeLove`。`queue.sqlite` 和 `local-models.txt` 统一放在该目录，不要求 EXE 所在的 Program Files 目录可写。即使 EXE 恰好位于可写目录，也不会自动切换成便携模式。

数据目录只接受本地盘绝对路径，不跟随网络目录或目录重解析点。用户目录不可用时不会悄悄改用当前工作目录、临时目录或新建另一份 EXE 邻接队列，而是停用相应队列/模型设置写入，保留原数据。模型中心的详情显示实际目录、旧目录与具体模式/迁移提示。

## 便携模式（显式启用）

在 EXE 同目录创建 `portable-mode.txt`，第一行内容为：

```text
RifeLovePortable 1
```

当程序目录的 `data` 可实际写入时，设置和队列继续使用 `EXE目录\data`，不另建用户配置副本。支持 UTF-8 BOM 和 CRLF。仅把程序放到可写目录并不足以启用便携模式。

如果便携数据目录不可写，会明确提示并尝试安装模式的用户目录。旧数据不会被删除；若旧目录或其中的文件无法安全读取/迁移，相应队列或模型设置保持停用，不能用空数据替代。标记无法读取或格式错误也会显示提示并使用安装模式规则。

## 从旧版本迁移

首次使用用户目录时，程序检查旧的 `EXE目录\data`。规则分别适用于队列和模型设置：

- 用户目录已有相应文件时，现有用户文件优先；不自动合并，也不覆盖它。旧文件继续保留，可作为历史副本。
- 用户目录尚无模型设置时，读取并验证旧 `local-models.txt`，把已验证的设置原子发布到新位置。中文模型路径和各类默认项保留，外部模型文件不会移动。
- 用户目录尚无队列时，先禁止旧数据库及其 WAL/回滚日志被并发写入，再将它们复制至新用户目录下的独立临时区。只有临时副本会交给 SQLite 恢复日志；随后通过 SQLite backup 和完整性检查生成自包含的新数据库，发布时禁止替换已有目标。旧 `queue.sqlite`、`-wal`、`-journal` 和 `-shm` 不删除、不修改。
- 旧队列仍由运行中的程序持有、文件无法读取、数据库损坏或发布失败时，保留旧件并停用此次新队列；模型设置迁移失败时禁止写入新默认设置。释放旧程序后可重启客户端重试。没有任何旧数据时才允许建立全新的空队列。

迁移不会搬动旧任务引用的视频、输出、外部模型和检查点文件，也不会重写任务中的绝对路径。请保留这些文件，并在切换后使用新版本继续工作；复制迁移后的新旧数据库不会互相同步，不要再用旧版本处理同一批任务。若两处已有不同历史，需由用户保留两份数据并明确选择后续处理位置，本阶段不做历史合并或清理。

## 验证范围

临时目录自动化用例覆盖默认 LocalAppData 选择、显式便携目录、便携回退、旧队列及已提交 WAL、中文模型偏好、已有用户文件优先、源文件被占用、损坏数据、目标不可用与原子设置替换失败。测试不接触真实用户配置或真实模型。对实际 Program Files ACL 和不同 Windows 用户配置的验收仍需在构建后执行；本次路径修复阶段只完成源码和静态检查，未自行构建或运行测试。
